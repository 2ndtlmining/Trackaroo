# Web Speed Implementation Plan (Phase 2 of the 28-Sep roadmap)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Every page is under 100 KB on the wire and under 20 ms to generate (warm) on today's data, and stays that way as the DB grows.

**Architecture:**
1. Compress every response in a tiny Node server that wraps the adapter-node handler. There is no proxy, which the owner confirmed on 28-Sep.
2. Stop shipping data nobody renders: the `/products` listings, the `/movers` rows with zero change, and the listing ids inside sparkline points.
3. Remove duplicate homepage queries.
4. Memoise day-level queries until SQLite's `data_version` says the pipeline wrote something.

The runtime stays SvelteKit. Measurements show payload size and query repetition are the problem, not the runtime (see the roadmap, "Why not Rust").

**Tech Stack:** SvelteKit 2 (adapter-node 5), Node 24, better-sqlite3 12, the `compression` npm package, vitest, Playwright.

**Spec:** Issues #28 and #5 (items 1–3 and 6), plus the 28-Sep speed audit in `docs/superpowers/plans/2026-09-28-roadmap.md`.

## Global Constraints

- Owner decision 28-Sep-2026: **compression in the Node server, no reverse proxy.**
- `/_app/immutable/*` is already served pre-compressed (br) with a one-year immutable cache. Do not double-compress it: the middleware must skip responses that already have `Content-Encoding`.
- The regression gate must be green before every commit:
  - from the repo root: `python -m pytest -q`
  - from `web/`: `npm run check`, `npm test`, `npm run test:e2e`
- No redeploy in this plan. The owner redeploys at the end of all phases. Dockerfile and entrypoint changes must still be made and build-tested here.
- Cached query results are **shared objects**. Callers must not mutate them: map or spread into new objects.

## Review Focus

1. **The pipeline writes new snapshots while the web app is running.** The next request must see the new data. This is the `data_version` invalidation, pinned in Task 4.
2. **A request without `Accept-Encoding`**, from curl or a health checker, must still get a correct, uncompressed body. Pinned in Task 1.
3. **Movers whose "Not enough history" rows have a `null` change** must sort last under every sort key, including `$ change` descending. Pinned in Task 3.
4. **`/movers?all=1`** must still show the unchanged and new listings for anyone who wants them. Pinned in Task 3.
5. **A price alert created or deleted on a product page** must show immediately after the redirect, not after a cache expiry. The write bumps `data_version`. Pinned in Task 4.

```js
// Production entry: adapter-node's handler behind gzip compression.
//
// adapter-node compresses nothing it renders; only the /_app/immutable
// assets ship pre-compressed. Measured 28-Sep-2026 on prod: /movers was
// 1.52 MB of HTML on the wire, 64 KB gzipped (#28). There is no reverse
// proxy in front (owner decision), so compression lives here.
import http from 'node:http';
import { pathToFileURL } from 'node:url';
import compression from 'compression';

// `compression` skips responses that already carry Content-Encoding, so the
// pre-compressed immutable assets pass through untouched.
const compress = compression({ threshold: 1024 });

export function createServer(handler) {
	return http.createServer((req, res) => {
		compress(req, res, () => {
			handler(req, res, () => {
				res.statusCode = 404;
				res.end('Not found');
			});
		});
	});
}

if (import.meta.url === pathToFileURL(process.argv[1] ?? '').href) {
	const { handler } = await import('./build/handler.js');
	const host = process.env.HOST ?? '0.0.0.0';
	const port = Number(process.env.PORT ?? 3000);
	createServer(handler).listen(port, host, () => {
		console.log(`Listening on http://${host}:${port}`);
	});
}
```

- [ ] **Step 4: `sortMovers`**

`movers.ts`:

```ts
export type MoverSortKey = 'abs' | 'pct' | 'price';

// Rows without a change ("Not enough history", null change) always sort last:
// sorting by |change| treated null as -Infinity, whose magnitude is Infinity,
// so brand-new listings led the page (#5).
export function sortMovers(rows: Mover[], key: MoverSortKey): Mover[] {
	const unknown = (m: Mover) => m.notEnoughHistory || m.change === null;
	return [...rows].sort((a, b) => {
		const ua = unknown(a), ub = unknown(b);
		if (ua !== ub) return ua ? 1 : -1;
		if (key === 'price') return b.newPrice - a.newPrice;
		if (ua) return a.listingId - b.listingId;
		if (key === 'abs') return Math.abs(b.change!) - Math.abs(a.change!) || a.listingId - b.listingId;
		return (b.pctChange ?? 0) - (a.pctChange ?? 0) || a.listingId - b.listingId;
	});
}
```

```ts
// Day-level query memo. The pipeline writes once a day, yet every request
// re-ran the same scans of price_snapshots (header stats 4x, deal candidates,
// movers). SQLite's data_version changes whenever ANOTHER connection commits,
// so the cache drops itself the moment the pipeline or an alert write lands --
// no TTL to tune, no stale page after a scrape.
//
// Values are shared between requests: callers must not mutate them.
import type { DB } from './db';

let version: number | null = null;
const store = new Map<string, unknown>();

export function memo<T>(db: DB, key: string, compute: () => T): T {
	const v = db.pragma('data_version', { simple: true }) as number;
	if (v !== version) {
		store.clear();
		version = v;
	}
	if (!store.has(key)) store.set(key, compute());
	return store.get(key) as T;
}

// Tests only.
export function _resetMemo(): void {
	version = null;
	store.clear();
}
```
